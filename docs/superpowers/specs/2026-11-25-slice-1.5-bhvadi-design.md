# Slice 1.5: the whole thematic class (bhvādi), present and past imperfective

Short design, agreed in conversation on 2026-11-25. It builds on the slice-1 design
(`2026-11-24-prakriya-engine-design.md`). Everything there still holds unless this
document says otherwise.

## Intent

Slice 1 derives laṭ/laṅ for seven roots. The user wants to watch the same machinery
work across the whole default thematic class. Each new rule needed should show up as
a visible, cited step. The tool stays a personal learning tool: readable derivations
matter more than coverage numbers.

## What counts as in scope

- **What "bhvādi" means.** It is the first section of the root list. Its roots take
  the thematic affix śap (3.1.68) by default, and more specific rules override that
  default for individual roots. So bhvādi is a default bin, not a morphological
  class (discussed with the user).
- **In:** every bhvādi root whose present stem is built with śap. That includes the
  roots whose stem 7.3.78 substitutes: pā → piba, ghrā → jighra, dhmā → dhama,
  sthā → tiṣṭha, mnā → mana, dā(ṇ) → yaccha, dṛś → paśya, ṛ → ṛccha, sad → sīda.
  These are still thematic; the substitution is one step.
- **Out** (marked "not yet available", with the reason and the governing sūtra):
  - nu-presents filed under bhvādi: śru → śṛṇoti (3.1.74), dhinv and kṛṇv (3.1.80).
    They are athematic and need strong/weak grade machinery, so they belong with
    the athematic classes.
  - derived stems: -āya- (3.1.28: gup, dhūp…), ṇiṅ (3.1.30: kam), desideratives by
    3.1.5–6 (gup, tij, mān, badh, kit, dān, śān), and optional śyan for kram (3.1.70).
  - nasal loss before śap: daṃś, rañj, sañj, svañj (6.4.25–26). These could go
    either way; they stay out unless they come almost for free, which is the
    builder's call.
- **Unchanged from slice 1:** tenses (laṭ, laṅ), voices, no preverbs, no accent,
  restricted siddha principle.

## New rules (from the laṭ 3sg sweep against Vidyut: 885/1153 right today)

| Rule | What it does | Roots affected |
|---|---|---|
| 7.1.58 idito num dhātoḥ | inserts a nasal into roots marked with an *i* marker, in every form | ~200 (kradi → krandati) |
| 6.4.24 aniditāṃ hala upadhāyāḥ kṅiti | drops the nasal of unmarked roots in weak forms | only to explain why 7.1.58 roots keep theirs; may not fire in laṭ/laṅ |
| 6.1.64 dhātvādeḥ ṣaḥ saḥ (+ ṇo naḥ, 6.1.65) | root-initial ṣ → s, ṇ → n; the retroflexion they caused is undone (ṣṭan → stan) | ~20 |
| 8.2.77–78 hali ca / upadhāyāṃ ca | lengthens i/u before r/v plus a consonant | ~19 (kurd → kūrdate) |
| 6.1.73 che ca | adds t before ch, which surfaces as cch | a few |
| 7.3.78 pāghrādhmā… | substitutes whole present stems | 9 roots |
| 7.3.77 iṣugamiyamāṃ chaḥ | already present: check it doesn't fire for yama~ (uparame) | yam |

**Display.** Each 7.3.78 step gets a short historical aside next to Pāṇini's
analysis, for example "historically a reduplicated present; cf. Lat. *bibit*". It
follows the existing "Read via" pattern, and the wording follows the modern-terms-first
convention.

**Bugs to fix:** vraj loses its v (and vraṇ too), the 3 UnresolvedConflict crashes
(yucham̐ and two others), and the parse of `chadiḥ`.

These are the known gaps. Full paradigms, laṅ in particular, may surface more. The
builder fixes those by the slice-1 rules: correct meta-rules, never ordering hacks.
Anything that needs a design decision goes back to the user.

## Approaches considered

- **A. Regular roots only.** Leave the 7.3.78 roots out. Rejected: they include
  some of the most common verbs, and the user picked B.
- **B. A plus the 7.3.78 substitutions (chosen),** with nu-presents deferred, as
  agreed.
- **C. Everything Vidyut lists in bhvādi.** Rejected: it pulls in derived stems and
  athematic presents, which are separate slices.

## Lexicon

- The bhvādi section of the root list is vendored as
  `src/panini/data/dhatupatha_bhvadi.tsv`: code, upadeśa (SLP1) and traditional
  gloss, taken from the Vidyut data (`build/vidyut-data/prakriya/dhatupatha.tsv`,
  1166 entries starting `01.`). Vidyut stays dev-only, and the runtime reads only
  the vendored file.
- **Root identity.** Roots are keyed by list code (01.0001), because many upadeśas
  repeat with different meanings (labi~ twice, for example).
- **Voice comes from the markers** (1.3.12 anudātta or ṅ marker → middle; 1.3.72
  svarita or ñ marker → both; otherwise active). It replaces the hand-set `pada`
  field and is cross-checked against Vidyut.
- **Glosses (my call).** The seven slice-1 roots keep their English glosses. Other
  roots show the traditional gloss in IAST (sattāyām), tagged as the traditional
  gloss. English glosses can be added later, root by root.
- **Availability.** Out-of-scope roots get a reason in `availability()`, which the
  GUI and CLI already use.

## Explorer (my call: a local server)

- **Why not the static page.** One HTML page with every derivation embedded would
  run to hundreds of MB. Today it is ~6 MB for 7 roots, most of it fonts.
  Derivation is fast (~2 ms a form, ~80 ms a paradigm).
- **`panini serve [--open]`** starts a small stdlib HTTP server on localhost:
  - it serves the same page;
  - it returns JSON for the root list, and for one root's paradigm with
    derivations, on request.
- **app.js gets a data source.** The page reads embedded data or fetches from the
  server. Nothing else in the UI changes.
- **`panini site`** still builds the self-contained static page, for a featured set:
  the slice-1 seven plus the 7.3.78 roots.
- **The root dropdown becomes a search box.** It matches the root in IAST
  (diacritic-insensitive), the list code, or the gloss. Results show the
  upadeśa, gloss and voice, and out-of-scope roots appear greyed out with their
  reason. The look stays in the existing app register.

## Checking

- **Full paradigms.** `scripts/make_reference.py` generates full Vidyut paradigms
  (laṭ/laṅ, both voices where available) for every in-scope root, about 40k forms
  in a JSON fixture of a few MB.
- **Fast tests (default):** the slice-1 roots, the 7.3.78 roots, and one or two
  roots per new rule.
- **Full sweep:** a pytest test marked `slow` runs every root against the fixture
  (~90 s). The goal is 100% agreement on in-scope roots, with remaining
  differences listed in `docs/findings.md` and explained (the same treatment
  slice 1 gave Vidyut differences).
