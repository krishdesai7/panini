# Slice 1.5 (whole bhvādi class) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Derive laṭ/laṅ for every in-scope bhvādi root (~1100), cross-checked against Vidyut, browsable through a local server with a root search box.

**Architecture:** The lexicon is read from a vendored copy of the bhvādi section of the root list, keyed by list code. The new rules go into the existing rule modules. They are ordinary `Rule` objects with notes in `{modern|traditional}` markup and are chosen by the existing resolver, with no ordering hacks. A stdlib HTTP server serves the existing page, which fetches one root's derivations at a time. The static page stays, for a featured set of roots.

**Tech Stack:** Python 3.15 via uv, pytest, stdlib `http.server`, vanilla JS (node for JS unit tests), Vidyut 0.4 (dev only).

**Spec:** `docs/superpowers/specs/2026-11-25-slice-1.5-bhvadi-design.md`. The slice-1 spec `docs/superpowers/specs/2026-11-24-prakriya-engine-design.md` still holds.

## Global Constraints

- All Python goes through uv: `uv run pytest`, `uv run --group dev python scripts/...`. Raw `python` is blocked.
- Vidyut is dev-only. Nothing under `src/` imports it, and the runtime reads only vendored data.
- Never fix a wrong form by reordering rules. Use correct meta-rules (blocking, `blocks`, conditions), and put any remaining difference in `docs/findings.md` plus the `XFAIL` table.
- Notes use `{modern|traditional}` markup, modern words first. Don't use "k-row"-style jargon. Optional rules just say "preferably". Lakāras are not "tenses".
- Scope: laṭ and laṅ, active and middle, no preverbs, no accent, restricted siddha principle.
- Commit after each task on branch `slice-1.5`. Don't merge to main.

## Review Focus

1. **A root name shared by several roots** (`smṛ` 01.0919/01.1082, `yam` 01.0930/01.1031/01.1139, `lab`…). `panini derive smṛ …` should pick the featured root. An ambiguous non-featured name should give a clear error listing the codes, never pick at random. Test in Task 1.
2. **Old URLs** like `#paṭh/laṭ/P/3/sg` (from slice-1 bookmarks) should still open paṭh, and an unknown code should fall back safely. Test in Task 10.
3. **The server receives a bad or out-of-scope code** (`/api/root/99.9999`, `/api/root/01.1092` śru). Expect 404 JSON for an unknown code, and "unavailable" derivations with reasons for out-of-scope roots, never a 500 or a hang. Test in Task 9.
4. **Placeholder rows** (`-` in the list, codes 01.0933–01.0944) must not become roots. Test in Task 1.
5. **Search with or without diacritics** (`krand` / `kRand` / `krand-`, `sthā` / `stha`, a code `01.0074`, a gloss word). Each finds the root, and the featured roots rank first on ties. Test in Task 10.
